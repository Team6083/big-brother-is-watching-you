# Bank 新任務通知

此功能在現有主 Bot 內定期查詢 Bank 網站，將新任務摘要送到指定的 Discord 文字頻道。狀態保存於 MongoDB，不需要另開程序、不經 Make，也不新增付費服務。預設停用；這份文件不代表正式伺服器已完成部署或驗收。

## 資料來源與判定方式

Bot 唯讀查詢來源網站的 `GET /api/gas-read?type=missionsList`。此端點由網站公開任務頁使用，回傳完整任務陣列，不需要登入或 API Key。Bot 不讀取隊伍接取紀錄、不接受任務，也不修改 Bank 資料。

任務資料包含 `id`、`title`、`description`、`category`、`level`、`type`、`status`、`startDate`、`deadline`、`rewardType`、`reward` 及 `rewardItem`。來源沒有 `publishedAt`；Bot 以任務 ID 是否首次出現在清單判定新任務，不能推定實際發布時刻。

1. 首次取得完整且有效的清單後，保存所有既有 ID 作為基準，不公告歷史任務。讀取失敗或資料格式錯誤時，不建立基準。
2. 後續出現的新 ID，只有狀態為「進行中」或「即將截止」，且截止日期空白或不早於台灣當日，才列入公告。
3. 開始日期不是發布時間，不作為公告門檻；未來才開始的新任務也會預告。
4. 已建立基準或已處理過的 ID，即使內容編輯、狀態重開或 Bot 重啟，也不會當成另一個新任務。新出現但當時不符合公告條件的任務會記為 `ignored`，後續不補發。

預設每 60 秒查詢一次。正常通知延遲約一個查詢間隔，加上來源網站快取、網路與 Discord 處理時間；來源失敗時會更久。任務若在兩次查詢之間建立後又刪除，Bot 可能看不到。

## 設定與權限

只在私密部署設定中填實際網址與 ID；公開範例不放團隊內部設定。

```dotenv
BANK_ENABLED=true
BANK_BASE_URL=https://bank.example.org
BANK_CHANNEL_ID=
BANK_INTERVAL_MS=60000
```

- `BANK_ENABLED`：預設 `false`；設為 `true` 才啟用。
- `BANK_BASE_URL`：來源網站的 HTTPS 根網址，不包含 `/mission` 或 API 路徑。
- `BANK_CHANNEL_ID`：指定伺服器內的通知文字頻道 ID，請由部署負責人私下填入。
- `BANK_INTERVAL_MS`：查詢間隔，單位為毫秒，預設 `60000`。

Bot 在該頻道需要 View Channel、Send Messages、Embed Links 及 Read Message History。讀取歷史用於核對送出結果不明的公告；不要求 Administrator，也不需要提及所有人的權限。通知不使用 @everyone 或自動提及使用者。

公告包含標題、任務描述、分類／類型、開始／截止日期、獎勵與原始任務連結，例如 `https://bank.example.org/mission/123`。日期只顯示網站資料，不替團隊設定期限或作出決策。

## 升級及啟用

維持現有單副本部署方式；本次不更動 CI/CD 或部署檔。

1. 部署負責人以更新版本及既有私密環境設定，先執行 `npm run migrate`，建立 `bank_notifications` collection 與必要索引。
2. 確認 Bot 已加入目標伺服器、能查看指定文字頻道，並有上述權限。
3. 填好四個 Bank 設定，啟用後執行既有的 `npm start`。不用另啟動 worker，也不用重新設定 Make。
4. 等待第一次清單完整讀取成功，確認基準已建立。此時既有任務不會收到通知。
5. 再於來源網站發布一筆實際測試用新任務，檢查頻道公告。這一步需要網站操作者配合，不由 Bot 自動新增測試資料。

資料庫有該專用 database 的 `readWrite` role 即可沿用；請勿清除 collection 來重置通知，因為會失去原本的去重及核對紀錄。

## 重試與去重

每個任務 ID 的狀態持久化保存於 `bank_notifications`：

| 狀態 | 意義 |
|---|---|
| `pending` | 符合公告條件，等待送出 |
| `sending` | 正在送出，結果尚未保存 |
| `sent` | Discord 已確認成功，保存訊息識別資料 |
| `failed` | 已知失敗，留下受控錯誤資訊供排查 |
| `uncertain` | 無法確定 Discord 是否已收到，不自動重送 |
| `ignored` | 基準內的歷史任務，或首次出現時不符合公告條件 |

來源 API 暫時性錯誤執行有限次數的退避重試。完整清單讀取失敗不當成空清單，也不刪除既有基準。

Discord 送出結果不明時，Bot 不直接重送，避免實際已發布卻重複公告。它可從目標頻道最近 100 則訊息中，核對自己發送的原任務連結，找到既有公告後補回成功紀錄。這個範圍有限；找不到不代表一定沒送出，需管理者查看頻道及日誌再處理。不得以猜測將 `uncertain` 視為成功或重新發送。

## 排查

- **完全沒有新公告**：確認 `BANK_ENABLED=true`、根網址、頻道 ID、Bot 權限及第一輪基準建立成功；首次基準本來就不補發歷史。
- **新任務沒有公告**：核對 ID 是否已在基準中、來源狀態、台灣日期下的截止日。內容修改或重新開放既有 ID 不觸發新公告。
- **來源讀取失敗**：確認部署環境可連線至來源 HTTPS 網站，查看受控 HTTP／資料格式錯誤。不要將真實任務清單或完整機密設定貼入公開 issue。
- **Discord 發送失敗**：核對通知頻道存在於設定的伺服器，以及 Bot 的查看、發送與嵌入連結權限。
- **`uncertain` 或重啟後留下 `sending`**：先在原頻道查找任務連結，讓歷史核對確認結果；若超出最近 100 則或無權讀取歷史，保留紀錄並人工排查。

## 人工端對端驗收

本機測試不代表團隊正式網站、Bot 權限與伺服器已驗收。部署後至少核對：

1. 啟用並建立基準後，歷史任務沒有被整批公告。
2. 新增開放任務後，指定頻道出現一次摘要，內容與網站一致，連結能開啟正確任務。
3. 預告未來開始的新任務；過期或未開放的新任務不公告。
4. 編輯同一任務及重新啟動 Bot，沒有重複公告。
5. 來源暫時無法連線後可恢復，既有基準及已送出紀錄仍保留。
6. Discord 權限不足時留下錯誤；送出結果不明時先核對歷史，沒有盲目重送。

驗收期間的任務新增、修改與清理由具權限的網站操作者處理。請先建立基準，再發布測試新任務；不要用啟用之前已存在的任務判定通知功能失效。
