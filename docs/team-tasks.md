# 隊長與幹部任務

## 管理員啟用

此功能由目前唯一的 Bot 程序提供，不開第二個 Bot、不開通付費服務，不修改 CI/CD 或部署檔。

1. 在伺服器的私密環境設定 `TASK_CONTROLS_ENABLED=true`，以 `TASK_ALLOWED_CHANNEL_IDS` 填入隊長、幹部文字頻道 ID（逗號分隔）。勿將實際部署設定提交至 public repo。
2. 沿用共用的 `TRELLO_BOARD_ID`、`TRELLO_API_KEY` 與具 read/write 權限的 `TRELLO_WRITE_TOKEN`。本功能直接呼叫 Trello，不經 Make，也不要求每位成員有 Trello 帳號。
3. `TASK_MANAGEMENT_MODE=forum` 代表所有可查看並發言的成員可建立／管理；`roles` 則仍需符合 `TASK_MANAGER_ROLE_IDS`。名稱沿用既有設定，檢查對象是當前任務所在頻道。
4. 在指定私人頻道授予 Bot：View Channel、Read Message History、Send Messages、Create Public Threads、Send Messages in Threads。不要授予 Administrator。人員選單只接受能查看、讀取歷史及發言（包括討論串）的人類成員。
5. 更新程式後，先執行 `npm run migrate`、`npm run check`、`npm run tasks:register`，再重啟唯一的 `npm start`。維持單副本及既有 Recreate 方式；不要同時啟動電腦舊版本。
6. 需到期提醒時設定 `PM_ENABLED=true` 與既有 Trello 讀取設定。通知只送到經 MongoDB 綁定的原任務討論串，不會送到另一個幹部／隊長頻道。

只有 `TASK_ALLOWED_CHANNEL_IDS` 有值且任務控制啟用時，才註冊 `/建立任務`。指令即使在其他頻道看得到，也會拒絕操作；Discord 管理員可另外限制指令顯示範圍。

## 成員操作

`/建立任務` 用於原本的隊長／幹部文字頻道；`/任務` 用於 Bot 已建立的任務討論串。直接在群聊使用 `/任務` 時，Bot 只會提示改用 `/建立任務`，不讀取或建立 Trello 卡片。

1. 在隊長／幹部文字頻道輸入 `/建立任務`，按「填寫任務」。
2. 填任務名稱、工作內容、完成標準、參考資料；用選單選 Owner（1–5 位）、Assignee（1–5 位）及狀態。預覽與後續「任務設定」會保留完整人員名單，既有單人 Assignee 任務仍可讀取及編輯。狀態直接使用共用看板的現有清單，不建立新分類。
3. 在只對自己顯示的預覽中選開始／截止日期。先選年、月，再選日；26 日以後按下一頁。月份天數與閏年自動計算，截止不可早於開始。日期可留空或清除；沒有日期文字輸入欄位。
4. 按「確認建立」。確認前取消不會建卡，也不會建立討論串。
5. 成功後到 Bot 提供的 Discord 討論串討論、查看任務及更新狀態。描述與設定只在建立時通知一次；後續不需反覆貼整份任務。

Bot 開的是私人文字頻道下的公開討論串（Discord 類型名稱），沿用父頻道的可見範圍。Trello 共用看板成員仍能讀取內容，這是共用看板既有的可見範圍。開始日為 Asia/Taipei 00:00、截止日為 23:59。

## 結果不明與重啟

- 在外部操作前先記錄操作編號。連點確認、重啟或回應遺失都不會讓相同操作再次 POST 建卡。
- Trello 回應不明時，按「核對建立結果」。Bot 只讀取同一 Thread ID 的卡片；只有一張且欄位符合當初提交內容，才確認成功並保存綁定。
- 原表單不在時，在原頻道使用 `/建立任務` 的「核對編號」選項，填原操作編號。此操作只供原建立者查詢；仍會重查當前權限。操作編號不是 Token。
- 找不到卡片、找到多張或欄位不一致時，維持待核對，請管理員核對 `task_creations` 及 Trello，不要反覆開新表單提交同一任務。
- 若 Discord 建立討論串的回應遺失，可能已有空討論串，`thread_pending` 仍保留。程式不猜測討論串、不自動重建；管理員應確認沒有正在進行的請求、核對 Discord 與 Trello。確認沒有任務卡後，再由人員清理空討論串及重新建立；不要直接把狀態改成成功。
- 任務已成功、但 @通知結果不明時，通知保留 `sending`，不重送，避免重複 @。原建立者仍會取得討論串連結，可自行查看。
- Bot 不會自動刪除失敗操作留下的討論串或 Trello 卡片。
- 隊長／幹部任務討論串若自動封存，只有已綁定同一張卡、且未鎖定時才允許 PM 發送提醒；送訊息會由 Discord 重新開啟討論串。鎖定、未綁定、其他頻道一律不發送；既有論壇的封存政策維持原樣。此行為依 [Discord Threads 文件](https://github.com/discord/discord-api-docs/blob/main/developers/topics/threads.mdx)，仍需用正式 Bot 權限驗收。

## 人工端對端驗收

1. 以真正的隊長或幹部帳號建立任務，確認年／月／日可選、月底可翻頁、描述模板與人員／狀態選單可用。
2. 預覽取消，確認 Discord 沒有新討論串、Trello 沒有新卡。
3. 確認建立，在共用看板只有一張卡，開始／截止時間與狀態正確；Owner／Assignee 無需 Trello 帳號。
4. 新討論串只有一則建立通知，@選定人員、顯示任務內容，不附 Trello 連結。
5. 由無父頻道權限的學生帳號確認無法讀取新討論串；從其他一般頻道使用指令應被拒絕。
6. 在新討論串執行 `/任務`，查看任務及修改狀態；確認變更反映至正確卡片。
7. 在測試環境安排接近到期的卡片，確認 PM 只在原討論串依 24 小時／1 小時／逾期階段提醒，完成狀態不提醒。
8. 在測試環境模擬回應遺失、重啟並使用原操作編號核對，確認沒有第二張卡或第二次 @通知。
