# 隊長與幹部任務

## 管理員啟用

此功能由目前唯一的 Bot 程序提供，不開第二個 Bot、不開通付費服務，不修改 CI/CD 或部署檔。

1. 在伺服器的私密環境設定 `TASK_CONTROLS_ENABLED=true`，以 `TASK_ALLOWED_CHANNEL_IDS` 填入隊長、幹部文字頻道 ID（逗號分隔）。要依這些頻道的 Discord 權限使用完整任務與會議功能，另明確設定 `TEAM_CHANNEL_ACCESS_ENABLED=true`。此開關預設 false；勿將實際部署設定提交至 public repo。
2. 使用現有 MongoDB 保存任務，先執行 `npm run migrate` 建立 `tasks` 與唯一索引，再執行 `npm run check`；不需要 Trello／Make 憑證。升級與舊資料匯入見 [MongoDB 任務](mongodb-tasks.md)。
3. 升級時若未設定 `TEAM_CHANNEL_ACCESS_ENABLED` 或設為 false，建立及編輯任務仍遵守 `TASK_MANAGEMENT_MODE`／`TASK_MANAGER_ROLE_IDS`，會議仍限原 `MEETING_CHANNEL_ID`。明確開啟新開關後，只有允許的隊長／幹部頻道及其任務討論串依 Discord 現有的查看、歷史與發言權限授權，不額外要求管理角色；提案論壇維持原政策。`TASK_CONTROLS_ENABLED=false` 也會關閉此擴充權限，原會議頻道的既有操作不受影響。
4. 在指定私人頻道授予 Bot：View Channel、Read Message History、Send Messages、Create Public Threads、Send Messages in Threads。不要授予 Administrator。人員選單只接受能查看、讀取歷史及發言（包括討論串）的人類成員。
5. 更新程式後，先執行 `npm run migrate`、`npm run check`、`npm run tasks:register`，再重啟唯一的 `npm start`。維持單副本及既有 Recreate 方式；不要同時啟動電腦舊版本。
6. 需到期提醒時設定 `PM_ENABLED=true` 。通知只送到經 MongoDB 綁定的原任務討論串，不會送到另一個幹部／隊長頻道。

只有 `TASK_ALLOWED_CHANNEL_IDS` 有值且任務控制啟用時，才註冊 `/建立任務`。指令即使在其他頻道看得到，也會拒絕操作；Discord 管理員可另外限制指令顯示範圍。

## 成員操作

`/建立任務` 用於原本的隊長／幹部文字頻道。`/任務` 可直接在已建立的任務討論串使用，也可在父文字頻道的「討論串」選項貼上此頻道下的任務討論串連結或 ID，查看／修改人員、描述、日期及狀態，或核對未確認更新。未指定討論串時只顯示操作說明。連結支援 discord.com、ptb.discord.com、canary.discord.com，可含訊息 ID、查詢參數或錨點；名稱及其他文字會提示改填連結或 ID。在任務討論串內指定其他討論串會被拒絕，避免改錯任務。每次操作都檢查原頻道與目標討論串權限，不能指定其他頻道的任務。

明確開啟上述兩個開關後，兩個允許頻道也都可使用 `/會議設定`、`/會議查看`、`/查看會議記錄`，包括編輯、取消與設定記錄連結。兩邊共用原本 `MEETING_CHANNEL_ID` 下的同一份會議及記錄；提醒仍只送到該提醒頻道，不另建會議或重複公告。需保留 `MEETING_CHANNEL_ID` 與 `MEETING_ROLE_ID` 設定，部署後重跑 `npm run tasks:register` 更新 `/任務` 的討論串選項。

1. 在隊長／幹部文字頻道輸入 `/建立任務`，按「填寫任務」。
2. 填任務名稱、工作內容、完成標準、參考資料；用選單選 Owner（1–5 位）、Assignee（1–5 位）及狀態。預覽與後續「任務設定」會保留完整人員名單，既有單人 Assignee 任務仍可讀取及編輯。狀態直接使用Bot 提供的七個任務階段。
3. 在只對自己顯示的預覽中選開始／截止日期。先選年、月，再選日；26 日以後按下一頁。月份天數與閏年自動計算，截止不可早於開始。日期可留空或清除；沒有日期文字輸入欄位。
4. 按「確認建立」。確認前取消不會建卡，也不會建立討論串。
5. 成功後到 Bot 提供的 Discord 討論串討論、查看任務及更新狀態。描述與設定只在建立時通知一次；後續不需反覆貼整份任務。

Bot 開的是私人文字頻道下的公開討論串（Discord 類型名稱），沿用父頻道的可見範圍。任務內容直接儲存在 MongoDB。開始日為 Asia/Taipei 00:00、截止日為 23:59。

## 結果不明與重啟

- 新版 `/任務` 面板的「查看任務」「核對未確認更新」會攜帶目標討論串 ID，Bot 重啟或草稿過期後仍能操作，且每次重查綁定及權限。舊版面板及編輯／狀態表單過期時，重新輸入 `/任務`；未確認的寫入仍保存在資料庫。
- 在外部操作前先記錄操作編號。連點確認、重啟或回應遺失都不會讓相同操作再次 POST 建卡。
- 任務寫入回應不明時，按「核對建立結果」。Bot 只讀取同一 Thread ID 的任務；只有一張且欄位符合當初提交內容，才確認成功並保存綁定。
- 原表單不在時，在原頻道使用 `/建立任務` 的「核對編號」選項，填原操作編號。此操作只供原建立者查詢；仍會重查當前權限。操作編號不是 Token。
- 找不到卡片、找到多項或欄位不一致時，維持待核對，請管理員核對 `task_creations` 與 `tasks，不要反覆開新表單提交同一任務。
- 若 Discord 建立討論串的回應遺失，可能已有空討論串，`thread_pending` 仍保留。程式不猜測討論串、不自動重建；管理員應確認沒有正在進行的請求、核對 Discord 與 MongoDB。確認沒有任務後，再由人員清理空討論串及重新建立；不要直接把狀態改成成功。
- 任務已成功、但 @通知結果不明時，通知保留 `sending`，不重送，避免重複 @。原建立者仍會取得討論串連結，可自行查看。
- Bot 不會自動刪除失敗操作留下的討論串或任務。
- 隊長／幹部任務討論串若自動封存，只有已綁定同一張卡、且未鎖定時才允許 PM 發送提醒；送訊息會由 Discord 重新開啟討論串。鎖定、未綁定、其他頻道一律不發送；既有論壇的封存政策維持原樣。此行為依 [Discord Threads 文件](https://github.com/discord/discord-api-docs/blob/main/developers/topics/threads.mdx)，仍需用正式 Bot 權限驗收。

## 人工端對端驗收

1. 以真正的隊長或幹部帳號建立任務，確認年／月／日可選、月底可翻頁、描述模板與人員／狀態選單可用。
2. 預覽取消，確認 Discord 沒有新討論串、MongoDB 沒有新任務。
3. 確認建立，MongoDB 只有一項任務，開始／截止時間與狀態正確；Owner／Assignee 直接選 Discord 成員。
4. 新討論串只有一則建立通知，@選定人員、顯示任務內容，不附外部看板連結。
5. 由無父頻道權限的學生帳號確認無法讀取新討論串；從其他一般頻道使用指令應被拒絕。
6. 明確開啟 `TEAM_CHANNEL_ACCESS_ENABLED=true` 後，在新討論串執行 `/任務`，再從原父頻道以討論串連結執行 `/任務`；兩處均可查看任務、編輯設定及修改狀態，確認變更反映至同一張卡片。以沒有額外管理角色的頻道成員驗證可操作；移除頻道發言權限後，舊表單不得繼續更新。
7. 在兩個允許頻道分別查看、設定、編輯及取消會議，補登與查詢記錄，確認共用同一份資料；其他頻道與無權成員不得操作。
8. 在測試環境安排接近到期的卡片，確認 PM 只在原討論串依 24 小時／1 小時／逾期階段提醒，完成狀態不提醒。
9. 在測試環境模擬回應遺失、重啟並使用原操作編號核對，確認沒有第二張卡或第二次 @通知；重啟前開啟的新版查看／核對按鈕仍能使用。
10. 未開啟新開關的舊 `roles` 設定，無指定管理角色者仍不能建立或更新任務；停用任務功能後，額外頻道不能操作會議。
